# Authentication And Setup

## Local Credential Source

The CLI auto-loads these private files when present:

- `~/.sos-contador/.env.local`
- `~/.sos-contador/.cuit_aliases.json`
- `~/.sos-contador/.cuit_catalog_cache.json`

Define `SOS_CONTADOR_HOME` to use another absolute private directory. New caches, drafts, document profiles, and exports are stored below that directory instead of the installed skill. For backward compatibility, the CLI may read a legacy `sos-contador-api/.env.local` only when the private file is absent; migrate it rather than relying on this fallback.

Load order:

1. process environment variables
2. values from `.env.local` for keys that are still unset

This means explicit env vars override the local file.

## Required Variables

For normal use, configure only:

- `SOS_CONTADOR_USUARIO`
- `SOS_CONTADOR_PASSWORD`

Community aliases also accepted by the CLI:

- `SOS_USUARIO`
- `SOS_PASSWORD`
- `SOS_API_BASE_URL`

Optional:

- `SOS_CONTADOR_HOME`
  - private runtime directory
  - default: `~/.sos-contador`
- `SOS_CONTADOR_BASE_URL`
  - default: `https://api.sos-contador.com/api-comunidad`
- `SOS_CONTADOR_SOFT_BASE_URL`
  - default: `https://soft.sos-contador.com`
- `SOS_CONTADOR_CA_BUNDLE`
  - ruta a un bundle PEM confiable cuando la red usa una autoridad certificante corporativa
  - si no se define, el cliente usa el bundle actualizado de `certifi` y mantiene activa la validación TLS

Deprecated and ignored for routing:

- `SOS_CONTADOR_CUIT_ID`
- `SOS_CONTADOR_CUIT`
- `SOS_CUIT_ID`
- `SOS_CUIT`

These variables may still exist in private local setups, but the CLI no longer uses them to choose the operational contribuyente.

## How Working CUIT Selection Works Now

The user must provide the `CUIT de trabajo` explicitly for every business operation.

Accepted forms:

1. explicit numeric CUIT
2. contribuyente name or alias resolved through `auth resolve-cuit --name ...`
3. a source document where the buyer/receptor section identifies a unique accessible CUIT

Discovery commands remain exempt:

- `auth info`
- `auth list-cuits`
- `auth resolve-cuit`

`auth web-info` is no longer discovery-only. It now requires an explicit working CUIT because it validates a pinned web-session for a specific contribuyente.

## Authentication Flow

The CLI separates user login from contribuyente binding.

Public API flow:

1. `POST /login`
   - body: `{"usuario":"...","password":"..."}`
   - extracts the user JWT
   - exposes the accessible CUIT catalog used by `auth list-cuits` and `auth resolve-cuit`
2. Bind explicitly to a working CUIT
   - by `--cuit-trabajo-id`
   - or by `--cuit-trabajo`
   - or by resolving `--cuit-trabajo-nombre`
3. `GET /cuit/credentials/:idcuit`
   - uses the user JWT as bearer token
   - extracts the operational token for that CUIT

Real response note:

- both `/login` and `/cuit/credentials/:idcuit` return the token under `jwt`

For `web-session` fallback, the CLI performs a direct HTTP login against:

- `https://soft.sos-contador.com/back/login.asp`

This is cookie-based, but still CLI-only. It does not open or reuse a browser.

## Validation

```powershell
python scripts/sos_contador_api.py auth info
python scripts/sos_contador_api.py auth list-cuits
python scripts/sos_contador_api.py auth resolve-cuit --name "empresa demo"
python scripts/sos_contador_api.py auth web-info --cuit-trabajo-nombre "empresa demo"
python scripts/sos_contador_api.py cobro list-range --cuit-trabajo <cuit_trabajo> --desde 01/11/2025 --hasta 30/11/2025
```

Expected behavior:

- `auth info` works without a selected CUIT and reports login/catalog state
- `auth list-cuits` lists the accessible contribuyentes discovered in `/login`
- `auth resolve-cuit --name ...` resolves a contribuyente from aliases plus cached catalog
- business commands fail fast when the working CUIT is missing

## Private Alias Files

The resolver supports two local-only files:

- `.cuit_catalog_cache.json`
  - autogenerated from `auth list-cuits`
  - stores `id`, `cuit`, `razon_social`, normalized name, and fetch time
- `.cuit_aliases.json`
  - manual
  - maps informal names like `empresa demo` to a canonical CUIT

These files belong under `SOS_CONTADOR_HOME` and must remain outside Git. The public template is:

- `cuit_aliases.example.json`

## Troubleshooting

- Missing credential values: the CLI tells you which variable is missing and points to `<SOS_CONTADOR_HOME>/.env.local`.
- Missing working CUIT: pass `--cuit-trabajo`, `--cuit-trabajo-id`, or `--cuit-trabajo-nombre`.
- Alias exists but CUIT no longer exists in SOS: the resolver refreshes the catalog and only accepts the alias if it still maps to a valid accessible CUIT.
- Cache is stale: the resolver refreshes it automatically when needed.
- Working CUIT not resolved: run `auth list-cuits` and use the explicit `id` or `cuit`.
- Login succeeded but JWTC failed: verify that the user has access to the selected CUIT and that the selected `idcuit` is correct.
- Deprecated env vars still present: they are ignored for routing and only reported by diagnostics such as `auth info`.
- TLS certificate validation fails: update the dependencies so `certifi` is current, or configure `SOS_CONTADOR_CA_BUNDLE` with the trusted corporate CA bundle. Never disable TLS verification.
- Web-session workflow: the same credentials are reused for `soft.sos-contador.com`, but the transport is direct HTTP plus cookies, not browser automation.
